Backups and snapshots

Updated 20 September 2026

Learn how NovelForge keeps your novel safe and how to bring an older copy back. Two separate features do the work, because they fail in different ways: backups copy the whole project, and versions keep earlier copies of a single document.

The layers that protect your writing

  • Safe saving. Every document is written to a temporary file, checked to be a valid Word file, and only then swapped in for the real one, so a crash in the middle of a save leaves the previous version untouched. A sync program such as OneDrive therefore sees either the old file or the new one, never a half-written one.
  • Autosave writes the scene you are typing in thirty seconds after you stop typing.
  • The recovery journal records your typing a second and a half after you pause. If the power goes out, the next start offers the words back and puts the cursor where you left it. Nothing is restored without asking.
  • Backups are zip files of the whole project, described below.
  • Versions are earlier copies of one document, also described below.
  • The trash and undo cover deletes: removed documents go to a _Trash folder, and Ctrl+Z puts them back. See The binder.

Backups

A backup is a single .zip of your whole novel folder, kept in the _Backups folder inside it. NovelForge makes one:

  • when you choose File → Back Up Now (Ctrl+B);
  • a moment after you open a novel, and again when you close it, unless you turn those off in File → Preferences under Safety (Backup when opening and Backup when closing).

The file name says when and why, for example The Ashfall Crown 2026-09-20 14-32-05 (manual).zip; the word in brackets is manual, open or close. NovelForge keeps the newest 25 backups and deletes older ones as new ones arrive. Backups to keep in Preferences changes that number.

What is inside

Everything in the novel's folder: your scenes and sheets, the maps, the compiled manuscripts, the trash, the drafts and project.json. Two things are left out on purpose: the _Backups folder itself (a backup of the backups would grow without limit) and _Snapshots. Word's temporary lock files (names starting with ~$) are skipped too, and a file that another program has locked is skipped rather than stopping the backup; the message afterwards says how many were skipped.

Verified, not just written

After writing a backup, NovelForge opens it again, checks every file in it against its stored checksum, and confirms that project.json is inside. If any of that fails, the file is deleted and you are told the backup failed; a broken zip never sits in the list looking like a good one. When the check passes, the status bar reports how many files were backed up and how large the zip is.

Seeing and restoring backups

File → Backups & Restore lists your backups, newest first, with the date, size and file name. Its buttons are:

  • Back up now makes a new one.
  • Verify re-checks the selected backup.
  • Restore to new folder asks you to choose an empty folder and unpacks the backup there.
  • Show in Explorer opens the _Backups folder.

Restoring never writes over the novel you are working on. You get a complete copy in the new folder, and you decide what to do with it: open it with File → Open Novel, or copy a single scene file out of it into your live project. NovelForge refuses to restore an archive that fails its check or contains unsafe paths.

When you open a novel whose newest backup is a week or more old, or that has none, the status bar says so.

The _Backups folder lives inside the novel's folder, so it protects you from mistakes and bad saves but not from losing the disk. Copy the folder, or just _Backups, to another drive or a synced folder now and then.

Versions of one document

Versions are earlier copies of a single Word document, kept in _Snapshots, one sub-folder per document. Choose a scene in the binder and then File → Versions of this document (or right-click the scene and choose Versions). The window lists every saved copy with its date and time and offers three buttons: Close, Open selected in Word and Restore selected.

Restoring is never destructive. The version now in place is first copied next to the document with (replaced and the time in its name, and only then is the older one put back. NovelForge keeps the newest 40 versions of each document; Snapshots per document in Preferences changes that.

When a version is made

A copy is taken automatically before NovelForge changes a document in bulk or swaps its content:

  • before Find and Replace edits a document, for each document it changes;
  • before you switch to another draft of a scene, so the text you are leaving is kept;
  • when you accept a crash recovery (the version replaced is also saved beside the scene as (before recovery)).

Typing and saving do not make versions. Autosave and Ctrl+S write over the scene file (safely) without keeping the old text, in this version of NovelForge. The Preferences window has a box called Snapshot on every save, but the writing area does not act on it. To get back to how a scene looked yesterday, restore a backup to a new folder and copy the scene out; and if you want to try a scene another way, use Drafts (Plan → Drafts of This Scene).

If something goes wrong

  • You deleted a scene: press Ctrl+Z. If you have closed the program since, look in _Trash via Edit → Open the Trash Folder.
  • A Find and Replace went too far: select the scene and open its versions; every changed document has one from just before the change.
  • The program or the computer stopped in the middle of writing: start NovelForge again and accept the recovery offer.
  • A scene is wrong and there is no version of it: restore the most recent backup to a new folder and copy the file across.
  • The whole folder is gone: restore the newest backup you have to a new folder, and open it.
